## Defect
The gate grepped only the target repo for a flag named in a row's acceptance criteria. Rows that
legitimately name flags of EXTERNAL CLIs (bunker, gitreins, kubectl, act) were failed with
'names a flag that does not exist', even though those CLIs are deliberately not vendored.
QA-HERMES-CANOPY-50 ('bunker destroy ... --purge') was the concrete false positive.

## Fix (fail-closed)
flag_owned_by_external_cli(): from the flag occurrence, scan up to 120 chars BACKWARD for a
candidate CLI token, keep only tokens resolvable via shutil.which(), then probe that CLI's
--help (cached, max 24 calls/row) with up to 3 following tokens, longest prefix first.
Match is a word-boundary regex: re.escape(flag) + '(?![\w-])', so --statuss cannot be
accepted by a help page that lists --status. A flag absent from the owner's help still FAILS.
