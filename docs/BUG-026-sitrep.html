BUG-026 — Nodes Page Crash: Root Cause, Fix & Regression Suite

Generated 2026-08-01 08:30 · Thread: KaraHermes · Owner: Bane · Workstream: coding-hermes

1. Executive Summary

The Nodes page (/nodes) crashed with TypeError: Cannot read properties of undefined (reading 'slice') whenever a tree was selected. Root cause: the page fetched the graph subtree endpoint, which returns minimal node summaries (id / tree / type / depth / dates only) — but the UI rendered node.authorId.slice(0,8) and node.content, which don't exist on those summaries. The crash left a blank page.

FIXED VERIFIED REGRESSION-LOCKED

2. Root Cause Analysis

LayerWhat happened
FrontendNodesPage.tsx fetched GET /graph/trees/{treeId}/subtree/{rootId} (the canvas renderer endpoint) and treated results as full nodes.
Contract gapNo GET /trees/{tree_id}/nodes list endpoint existed. The spec documented create/update/delete/reply/fork but no GET endpoints at all.
BackendGraphNodeSummary deliberately omits content/author — payload-size optimization for the graph canvas. The repo's GetByTree already returned full nodes; the service layer never exposed it.
TriggerAny tree selection on /nodes → authorId.slice on undefined → blank page.

Fix strategy

Add the missing list endpoint backed by full NodeDetail objects, and point the Nodes page at it. The subtree endpoint stays minimal for the canvas — two correct contracts instead of one overloaded one.
